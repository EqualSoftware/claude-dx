# ADR-006: Manage documents with MCP tools

- Status: Accepted
- Date: 2026-10-25
- Owners: Maintainer

## Context
Without tools, the model reads a template, lists a directory, finds the next number, writes the file and updates an index. This uses approximately 6 tool calls and gives different results each time. The reference skills are in the [equal workflow](https://github.com/is-equal/claude-equal-workflow/tree/main/plugins/equal/skills) (`adr`, `task`, `eukera`, `glossary`).

## Decision

- Fixed paths. No configuration in v1:
  - ADRs: `docs/decisions/ADR-NNN-<short-kebab-title>.md` and `docs/decisions/README.md`
  - Tasks: `docs/tasks/TASK-NNN-<short-kebab-title>.md` and `docs/tasks/README.md`
  - Learnings: `docs/learnings/<topic>.md` and `docs/learnings/README.md`
  - Glossary: `docs/GLOSSARY.md`
- A create tool makes the directory if it does not exist. Other tools do not make directories. If the directory or file does not exist, they return a message, not an error. Example: `No ADRs. docs/decisions does not exist.`
- The binary embeds the templates. The ADR template is the equal ADR template. The task template is the equal task template with these changes: section 8 has no `Agent` column; Definition of Done uses "Project checks (build, tests, lint) pass" and `/dx:eureka`, and has no `equal-tasks-index` item. The task fields are in the frontmatter, not in a Field/Value table (ADR-013): `id`, `title`, `status`, `priority`, `milestone`, `type`, `size`, `owner`, `platforms`, `area`, `depends_on`, `related`. `milestone` is required and is `vMAJOR.MINOR.PATCH`, example `v0.1.0` (TASK-030).
- ADR tools: `adr_list`, `adr_get`, `adr_create`, `adr_update`, `adr_supersede`. No delete tool. A replaced ADR gets `Superseded by ADR-NNN`. Supersede rules (TASK-021): the new ADR must be `Accepted`; an old ADR that is already superseded cannot get a second replacement; `adr_update` cannot change the status of a superseded ADR, but it can change its sections. These rules also stop cycles.
- Task tools: `task_list` (a filter for each frontmatter field, and `status: ready` for the `Approved` tasks with all dependencies `Done`, in milestone order, then priority order), `task_get` (all, or one section), `task_create`, `task_update_section`, `task_update_fields` (frontmatter fields), `task_set_status`, `task_question_add`, `task_question_answer`, `task_dod_check`, `task_renumber`. No delete tool. A task that stops gets `Cancelled`.
- `task_set_status` enforces the status rules of the equal task skill: `Approved` needs no `Open` question; `Done` needs all Definition of Done items checked; each change adds a Document History row.
- Each document folder has a generated index `README.md` (TASK-036). GitHub shows it under the file list of the folder. Each write of a task, an ADR or a learning makes the `README.md` of its folder again: the task index has one table of open tasks for each milestone in version order and one table of closed tasks, the ADR index has `| ADR | Title | Status | Date |`, the learning index has `| Topic | Description |`. The indexes are for persons on GitHub and for persons with no claude-dx. Their first line is `<!-- Generated by claude-dx. Do not edit. -->`. The model does not read them. The model uses `task_list`, `adr_list` and `learning_list`. The learning tools do not list `README.md` as a learning and refuse the topic `readme`.
- Learning tools: `learning_list` (topic and description), `learning_get`, `learning_create` (refuses a topic that exists), `learning_update`, `learning_delete`. Frontmatter: `topic`, `description`.
- Glossary tools: `glossary_lookup` (also searches the `Do not use` column), `glossary_list` (all rows, filter: area; TASK-020), `glossary_upsert` (keeps alphabetical order), `glossary_delete`. Columns: `Term | Definition | Area | Do not use | Source`. The glossary is one file and it is its own index.

## Alternatives

- Skills only, with no MCP tools: rejected. More tool calls and different results each time.
- No generated index: rejected. Persons on GitHub lose the overview of the documents.
- A task index with an other file name than `README.md`: rejected (TASK-036), because GitHub shows only a `README.md` in the folder view.
- One index for all documents in `docs/README.md`: rejected, because each folder index stays near its files.
- Configurable paths: rejected for v1. Fixed paths are simpler.

## Consequences
- Positive: one tool call for each document change. Same format each time.
- Negative: the templates are fixed in the binary. A change needs a release.
- Follow-up: ADR-007 defines number allocation.
