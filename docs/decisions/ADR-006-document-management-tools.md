# ADR-006: Manage documents with MCP tools

- Status: Accepted
- Date: 2026-10-25
- Owners: Maintainer

## Context
Without tools, the model reads a template, lists a directory, finds the next number, writes the file and updates an index. This uses approximately 6 tool calls and gives different results each time. The reference skills are in the [equal workflow](https://github.com/is-equal/claude-equal-workflow/tree/main/plugins/equal/skills) (`adr`, `task`, `eukera`, `glossary`).

## Decision
- Fixed paths. No configuration in v1:
  - ADRs: `docs/decisions/ADR-NNN-<short-kebab-title>.md`
  - Tasks: `docs/tasks/TASK-NNN-<short-kebab-title>.md` and `docs/tasks/INDEX.md`
  - Learnings: `docs/learnings/<topic>.md`
  - Glossary: `docs/GLOSSARY.md`
- A create tool makes the directory if it does not exist. Other tools do not make directories. If the directory or file does not exist, they return a message, not an error. Example: `No ADRs. docs/decisions does not exist.`
- The binary embeds the templates. The ADR template is the equal ADR template. The task template is the equal task template with these changes: section 8 has no `Agent` column; Definition of Done uses "Project checks (build, tests, lint) pass" and `/dx:eureka`, and has no `equal-tasks-index` item.
- ADR tools: `adr_list`, `adr_get`, `adr_create`, `adr_update`, `adr_supersede`. No delete tool. A replaced ADR gets `Superseded by ADR-NNN`.
- Task tools: `task_list` (filters: status, priority, area), `task_get` (all, or one section), `task_create`, `task_update_section`, `task_set_status`, `task_question_add`, `task_question_answer`, `task_renumber`. No delete tool. A task that stops gets `Cancelled`.
- `task_set_status` enforces the status rules of the equal task skill: `Approved` needs no `Open` question; `Done` needs all Definition of Done items checked; each change adds a Document History row.
- Each task write makes `docs/tasks/INDEX.md` again. It is for persons on GitHub and for persons with no claude-dx. Its first line is `<!-- Generated by claude-dx. Do not edit. -->`. The model does not read it. The model uses `task_list`.
- Learning tools: `learning_list` (topic and description), `learning_get`, `learning_create` (refuses a topic that exists), `learning_update`, `learning_delete`. Frontmatter: `topic`, `description`.
- Glossary tools: `glossary_lookup` (also searches the `Do not use` column), `glossary_list` (all rows, filter: area; TASK-020), `glossary_upsert` (keeps alphabetical order), `glossary_delete`. Columns: `Term | Definition | Area | Do not use | Source`.

## Alternatives
- Skills only, with no MCP tools: rejected. More tool calls and different results each time.
- No `INDEX.md`: rejected. Persons on GitHub lose the overview of tasks.
- Configurable paths: rejected for v1. Fixed paths are simpler.

## Consequences
- Positive: one tool call for each document change. Same format each time.
- Negative: the templates are fixed in the binary. A change needs a release.
- Follow-up: ADR-007 defines number allocation.
