# Rules shared by the doc tools

## 1. Summary

The doc tools share these rules: titles, file names, README indexes, frontmatter edits, file mode, renames, the docs lock and the atomic write. The rules apply to tasks, ADRs, learnings, specs and the glossary.

## 2. Problem

Each doc tool needs the same checks. Without shared rules, a title can be too long, a write can change the file mode, and an index row can break its table.

## 3. Goals

- G-1: Each new title has 40 characters or less, and has an ASCII letter or digit.
- G-2: Each file name has a slug of 40 characters or less.
- G-3: A doc write keeps the file mode, and one document has one file.
- G-4: No edit of a dx document is lost when two sessions change it at the same time.
- G-5: A reader sees the old or the new content of a file, never a partial file.

## 4. Out of Scope

- Rules of one document kind: they are in the spec of that kind.
- The cache lock: see the spec session.
- The number allocation, the project data directory and the lock files: see the spec project-data.

## 6. Design

### Modules

- `internal/docs/docfile`: `CheckTitle` and `MaxTitle` (40), `Slug`, `Cell` (escapes the pipe character), `Locked` and `RLocked` (exclusive and shared docs lock, with one `sync.RWMutex`), `Write` (temporary file, rename, mode of the existing file), `Move` (one rename, refuses an existing target).
- `internal/docs/adr`, `internal/docs/learning`, `internal/docs/spec`: each has an `index.go` that writes the generated `README.md` of its folder.
- `internal/markdown/frontmatter.go`: `SetField` replaces a key and its continuation lines.

### Data flow

1. A change takes the exclusive docs lock for the whole read, change and write. A read takes the shared docs lock.
2. A tool checks the title, writes the document with `docfile.Write`, and then writes the README index of its folder.
3. The tool releases the lock.

### Formats

- File names: `ADR-NNN-<slug>.md`, `docs/specs/<slug>/SPEC.md` and `docs/learnings/<topic>.md`. The slug of an ADR has 40 characters or less.
- Index header: `<!-- Generated by claude-dx. Do not edit. -->`.
- Index rows: a `|` in a title or a description is written as `\|`.

### Decisions

- ADR-002: document tools and paths.
- ADR-006: the write rule (temporary file and rename) and the read and write locks. This spec links to them and does not repeat them.
- ADR-007: number allocation.
- ADR-012: one subject for each spec.

- R-6: `TestIndexEscapesPipes` in `internal/docs/adr` and `internal/docs/learning`, and `TestCell` (`internal/docs/docfile`).
- R-7: `TestSetFieldReplacesBlockValue` and `TestSetFieldReplacesLine` (`internal/markdown`).
- R-8: `TestWriteKeepsMode` (`internal/docs/docfile`).
- R-9: `TestMoveExists` and `TestMoveOpenFile` (`internal/docs/docfile`).
- R-10: `TestLocked`, `TestRLockedShares`, `TestNoLockPath` (`internal/docs/docfile/write_test.go`). The 20-goroutine edit test is in `internal/docs/task/lock_test.go`.
- R-11: `TestWrite`, `TestWriteFails`, `TestWriteOpenFile` (`internal/docs/docfile/write_test.go`) and `TestWriteKeepsMode` (`write_unix_test.go`).

The tests pass on macOS, Linux and Windows.
